### GETの場合
#### イメージ

GET /pokemon?id=25
「25番のポケモンください」

#### パラメータ

URLの後ろについているもの
https://example.com/pokemon?id=25

この
?id=25
がパラメータ

もっと複数あると
https://example.com/pokemon?id=25&name=pikachu
です。

Reactだと
fetch("/pokemon?id=25")
になります。

#### リクエストヘッダ

裏で送る情報

例えば
Authorization: Bearer xxxxx
Content-Type: application/json
など。

##### よくある例
fetch("/pokemon?id=25", {
headers: {
Authorization: "Bearer abc123"
}
})

#### リクエストボディ

GETは基本的に使わない。

つまり

GET
↓
パラメータで指定
↓
ボディなし

です。

初心者はまず
GET = ボディなし
と思ってOK。

#### レスポンスヘッダ

サーバーから返る説明書

例えば
Content-Type: application/json
Status: 200
とか。

##### レスポンスボディ

本当に欲しいデータ。

例
{
"id": 25,
"name": "pikachu"
}

これをReactで使います。

##### GETを図にすると

**React**
GET /pokemon?id=25
↓
【リクエスト】
- URL： /pokemon
- パラメータ：あり(パラメータが付くことが多い) ?id=25
- リクエストヘッダ：あり Authorization
- リクエストボディ：なし
 
────────── 
**Server**
【レスポンス】 
↓
- ステータスコード：あり 200 OK
- レスポンスヘッダ：あり Content-Type: application/json
- レスポンスボディ：あり  {"id": 25,"name": "pikachu"}
---
### POSTの場合

POSTはデータを登録したいときに使う。

例えば会員登録
- 名前
- メール
- パスワード
を送る。

#### パラメータ
POSTでも付けられる。
/users?type=normal

ただあまり使われない。


#### リクエストヘッダ
GETと同じ。
例
Content-Type: application/json


#### リクエストボディ

POSTの主役。
{
"name":"山田",
"mail":"aaa@test.com"
}

##### fetchの例
fetch("/users", {
method: "POST",
headers: {
"Content-Type": "application/json"
},
body: JSON.stringify({
name: "山田",
mail: "aaa@test.com"
})
})


#### レスポンスボディ

登録結果が返る。
{
"id": 100,
"name": "山田"
}

#### POSTを図にする
**React**
POST /users
【リクエスト】
- URL： /users
- パラメータ：なし（使えるけど、あまり使われない）
- リクエストヘッダ：あり（必要なら付ける） 
    - Content-Type: application/json
    - Authorization
- リクエストボディ：あり（通常あり）
  -  {"name":"山田","mail":"aaa@test.com"} 
──────────
**Server**
【レスポンス】  
- ステータスコード：あり 200 OK
- レスポンスヘッダ：あり Content-Type: application/json
- レスポンスボディ：あり
  - {"id": 100,"name": "山田"}
